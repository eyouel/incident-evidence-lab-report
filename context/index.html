What this run establishes

Both operating profiles use the same Qwen3 8B weights and corrected native tool interface. The model chooses its own reads. A trusted broker supplies permitted observations. A separate checker rejects unsupported claims; an independent evaluator grades the result. Valid JSON alone is not a successful investigation.

Setup, repeated incident checks, fixture comparisons and saved Java replay are separate results. A correct unknown answer is useful uncertainty, not a known-outcome resolution. Checker rejection is never credited as abstention.

The input limit now uses the real tokenizer

The first blocked N/plain fixture request stopped at a conservative byte-based estimate before a record could be read. Eleven earlier Java comparisons had already read records before that guard stopped them. The host now renders the complete native conversation with the pinned runtime and tokenizes that exact prompt with the owned local runner. It keeps every instruction, declared action, prior call and returned observation. It reserves 8,192 output tokens plus one runtime position within the unchanged 32,768-token context. No input is shortened and no evidence is silently removed.

The exact first previously blocked request contained 28,354 HTTP JSON bytes and 25,385 rendered prompt bytes. The old estimate was 27,892; the actual tokenizer counted 5,687 input tokens. Across 55 checked complete input shapes, the largest count was 9,826.

A deliberately oversized complete rendered prompt was rejected before generation. Capacity probes used no model generations. This checks admission mechanics; it does not demonstrate a correct diagnosis or promise that every future history will fit. Tokenizer helpers share the same request ledger and deadlines as generation.

Two documented operating profiles

N disables thinking and uses temperature 0.7/top-p 0.8. T enables thinking and uses temperature 0.6/top-p 0.95. Both use top-k 20/min-p 0. Other supported sampling settings, evidence, limits and policy texts are held equal. This compares complete profiles; it cannot isolate a causal effect of thinking alone.

Each investigation has eight generations, 600 seconds including startup/model waiting, and the original query/byte/row limits. Each request has 300 seconds and 8,192 output tokens reserved inside a 32,768-token context. There is no automatic retry, prompt trimming or answer repair.

Qwen3-8B recommends excluding thinking from later history. The host preserves actual assistant tool calls and real tool replies, while discarding raw thinking. Safe presence/length metadata and runtime-reported usage remain. Effective initial and returned-tool renders verified the requested modes.

Input admission and diagnostic failures are different

A measured input-budget stop happens before generation. A runtime context or transport failure happens at a different boundary and retains its exact error. Neither is a model answer. An invalid-schema action is the model submitting arguments outside the unchanged contract; checker rejection is a further, separate judgment about support. None is counted as valid uncertainty. Categories may overlap within one investigation.

The final supported clean-source suite passed 708 tests in 127.17 seconds, with no skips. Read-only review then corrected two summary sentences; the affected 26 publication tests passed from a second clean source export in 4.07 seconds. These test counts overlap and must not be added.
