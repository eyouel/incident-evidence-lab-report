What problem does this lab test?

An application accepts work, calls another service, and asks a worker to finish it. The application writes records about these steps. A record about completion can disappear even when the work finished.

If we keep fewer records, can we still tell whether work finished or failed? We test that question before recommending which records to keep. Missing records alone cannot prove failed work.

This application and its incident examples were created for this project. They contain synthetic data. No workplace incident or customer data is used.

How the parts work

  1. The application creates evidence. The Java example accepts an order, calls inventory, and commits one worker result. Traces, logs, and saved status describe the work.
  2. The replay chooses records. Original records, fewer records, and selected restorations keep the same incident and time cutoff.
  3. A trusted reader enforces limits. The investigator can request only permitted evidence reads. It gets no file, shell, browser, credential, or answer-key access.
  4. The investigator proposes an answer. Each model trial starts with a fresh conversation. Plain and candidate policies use the predeclared order and one selected model.
  5. A separate checker verifies structured claims. It checks evidence references, work identity, and times. It cannot verify every sentence or a claimed cause.
  6. A separate evaluator scores the saved answer. Fixture scores check outcome and required failure location. Java scores check outcome only. The report keeps these scores separate.

A final answer, a checker verdict, and an evaluator score are three different records. Open the model trial to inspect all three. The development assistant did not act as the evaluated investigator.

What these results cannot establish

  • Five synthetic cases and one captured Java operation do not establish production accuracy or universal compatibility.
  • Restoration adds records saved earlier. It does not create records that were never collected, repair an application, or explain every missing trace.
  • A smaller evidence file is not measured financial savings. Local inference has no provider-token charge; electricity, hardware, and total operating cost are not measured here.
  • Local-model results are separate from the unexecuted OpenAI API and subscription-investigator experiments. Neither of those experiments is complete.
  • The site is static. Its controls read saved data only. It has no model endpoint, uploads, tracking, or execution button.
  • Published copies omit private fields and raw model reasoning. Original execution hashes remain identifiers of the original inputs, not hashes of these sanitized copies.
